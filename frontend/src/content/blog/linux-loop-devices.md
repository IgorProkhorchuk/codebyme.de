На Ubuntu з пакетами Snap команда `lsblk` показує поруч із дисками пристрої на кшталт `loop0` і `loop1`. За точкою монтування можна впізнати пакет і ревізію. Наприклад, `/snap/core24/1200` — це ревізія 1200 пакета `core24`.

У [статті про створення пакета Snap](/blog/creating_a_snap_on_ubuntu_and_linux) показано збирання застосунку в один файл `.snap`. Після встановлення Linux дає ядру доступ до цього файла через loop-пристрій. Той самий механізм можна використати для власного образу, наприклад щоб створити маленьку файлову систему (ext4, exFAT тощо) і перевірити, як вона поводиться, не змінюючи розділів диска.

## Як файл стає блоковим пристроєм

SSD, розділ диска й логічний том LVM доступні Linux через інтерфейс блокового пристрою. Він дає ядру змогу читати й записувати дані за позиціями всередині пристрою. Драйвер файлової системи використовує цей інтерфейс, щоб знайти свої метадані, каталоги та вміст файлів.

Loop-пристрій надає такий самий інтерфейс через `/dev/loopN`, але для зберігання даних використовує звичайний файл, який називають *backing file*. Наприклад, запит на читання даних із певного зміщення в `/dev/loop12` перетворюється на читання відповідної ділянки `test.img`. Сам файл лежить у файловій системі хоста, яка вже працює на SSD чи іншому сховищі. [Драйвер loop у ядрі Linux](https://github.com/torvalds/linux/blob/master/drivers/block/loop.c)

```text
Файл на диску       Блоковий пристрій      Файлова система      Каталог
test.img        →    /dev/loop12        →   ext4              →   /mnt/lab
```

`losetup` прив’язує файл до блокового пристрою. Форматування записує у файл структури файлової системи, а `mount` відкриває її вміст через каталог.

## Навіщо Snap використовує loop

Файл `.snap` уже містить готову стиснену файлову систему SquashFS. Під час встановлення snapd зберігає файл пакета, зазвичай у `/var/lib/snapd/snaps/`, та організовує його монтування через loop. На Ubuntu вміст ревізії доступний за шляхом на зразок `/snap/hello-snap/42/`. Посилання `current` вказує на активну ревізію. Записувані дані застосунку лежать окремо, наприклад у каталогах, на які вказують `$SNAP_DATA` і `$SNAP_USER_DATA`. [Розташування даних Snap](https://snapcraft.io/docs/reference/administration/data-locations/)

Snapd монтує образ пакета без попереднього розпаковування в системні каталоги. SquashFS розпаковує блоки під час читання. Образ змонтовано лише для читання, тому застосунок не може випадково змінити файли пакета. Якщо попередня ревізія збережена, snapd може повернутися до її образу. [Формат пакета Snap](https://snapcraft.io/docs/reference/development/yaml-schemas/the-snap-format/)

Кожен змонтований образ потребує окремого пристрою й точки монтування. Якщо система зберігає кілька ревізій, їхні файли займають місце на диску. Під час читання є додатковий шар між SquashFS і сховищем, а розпакування блоків витрачає процесорний час. Вплив на швидкість залежить від розміру образу, стиснення, кешу й характеру доступу. У контейнері також можуть бракувати прав або доступу до драйверів loop та SquashFS, необхідних для монтування.

Кількість рядків `loop` у `lsblk` сама по собі нічого не каже про втрати продуктивності. І вона не дорівнює кількості встановлених застосунків. Окремі образи можуть належати базовим пакетам, службам і різним ревізіям. Перелік установлених ревізій дивіться через `snap list --all`. [Ревізії Snap](https://snapcraft.io/docs/revisions/)

## Як читати вивід lsblk

можна задати колонки явно, щоб бачити і тип пристрою, і файлову систему, і місце монтування.

```bash
lsblk -o NAME,MAJ:MIN,TYPE,SIZE,RO,FSTYPE,MOUNTPOINTS
```

Приклад виводу для системи з одним NVMe-диском і двома змонтованими образами Snap:

```text
NAME        MAJ:MIN TYPE   SIZE RO FSTYPE   MOUNTPOINTS
loop0         7:0   loop  68.5M  1 squashfs /snap/core24/1200
loop1         7:1   loop  14.2M  1 squashfs /snap/hello-snap/42
nvme0n1     259:0   disk 476.9G  0
├─nvme0n1p1 259:1   part   512M  0 vfat     /boot/efi
└─nvme0n1p2 259:2   part 476.4G  0 ext4     /
```

`disk` і `part` описують диск і його розділи. `loop` описує спосіб підключення образу, а `squashfs` — формат файлової системи всередині. `RO=1` позначає пристрій лише для читання. У парі `7:0` число `7` є основним номером (*major*) драйвера loop, а `0` — додатковим номером (*minor*) цього пристрою. `SIZE` для loop показує розмір пристрою, який бачить ядро. Це не обсяг окремо виділеного фізичного диска.

Якщо треба побачити, до якого файла прив’язано кожен пристрій, можна скористатися `losetup`. Вивід пов’яже, наприклад, `/dev/loop1` із конкретним файлом `.snap` у `/var/lib/snapd/snaps/`.

```bash
sudo losetup --list --output NAME,BACK-FILE,RO
```

`lsblk` відповідає на запитання «які блокові пристрої є в системі». Якщо цікавлять саме змонтовані файлові системи SquashFS та їхні каталоги, зручніше подивитися таблицю монтувань.

```bash
findmnt -t squashfs -o SOURCE,TARGET,FSTYPE,OPTIONS
```

У `df` образ SquashFS часто показує `100%` використання. Файлова система сформована під готовий вміст і не має вільних блоків для запису. Щоб оцінити залишок місця для нових пакетів, можна переглянути файлову систему, на якій зберігаються самі образи.

```bash
df -h /var/lib/snapd/snaps
```

### Як переглянути всі блочні пристрої без loop

Особисто мене бісить, коли `lsblk` показує десятки loop-пристроїв, а треба подивитися лише реальні диски й розділи.

можна відфільтрувати пристрої з major-номером `7`.
(_Major-номер вказує ядру системи, який саме драйвер (програмний модуль) відповідає за роботу з цим типом обладнання. Усі пристрої, які мають однаковий major-номер, керуються одним і тим самим драйвером._ Наприклад, 8 — драйвер для SCSI/SATA дисків та USB-накопичувачів, 7 — драйвер для віртуальних loop-пристроїв, 259 — драйвер для швидкісних NVMe-накопичувачів.)

```bash
lsblk --exclude 7 -o NAME,TYPE,SIZE,FSTYPE,MOUNTPOINTS
```

```text
NAME        TYPE   SIZE FSTYPE MOUNTPOINTS
nvme0n1     disk 476.9G
├─nvme0n1p1 part   512M vfat   /boot/efi
└─nvme0n1p2 part 476.4G ext4   /
```

Команда фільтрує верхній рівень дерева `lsblk` і прибирає звідти loop-пристрої разом із їхніми гілками. Вона діє лише на вивід команди. Інші типи віртуальних пристроїв, наприклад томи LVM, можуть залишитися у списку. На старіших версіях `lsblk`, де немає `MOUNTPOINTS`, можна вказати `MOUNTPOINT`. [Документація lsblk](https://man7.org/linux/man-pages/man8/lsblk.8.html)

У `df` фільтр працює інакше. Він вибирає файлові системи, тому `df -h -x squashfs` прибере всі SquashFS, але залишить, наприклад, змонтований ext4 на loop-пристрої.

## Як створити власний образ і змонтувати його як loop-пристрій

Створимо ext4 у новому файлі розміром 256 МіБ, під’єднаємо його як loop-пристрій і запишемо тестовий файл. Для прикладу потрібні Linux із підтримкою loop та ext4, команди `losetup` і `mount` з util-linux, а також `mkfs.ext4` з e2fsprogs. Форматування й створення файла виконаємо від звичайного користувача. Для прив’язки пристрою та монтування знадобиться `sudo`.

### Крок 1: Створюємо образ

Створіть новий каталог у домашній директорії.

```bash
mkdir ~/loop-test
```

Решту команд виконуйте з каталогу.

```bash
cd ~/loop-test
```

`dd` зчитує нульові байти з `/dev/zero` і записує їх у `test.img`.

створимо файл `test.img` розміром 256 МіБ.

```bash
dd if=/dev/zero of=test.img bs=1M count=256 conv=excl
```

Параметр `conv=excl` зупинить команду, якщо файл уже існує.

```bash
ls -lh test.img
```

### Записуємо файлову систему ext4

Поки що `test.img` містить лише нулі. `mkfs.ext4` запише в нього метадані ext4, зокрема суперблок і таблиці inode. Параметр `-F` дозволяє форматувати звичайний файл. Передавайте команді саме новий `test.img`, оскільки форматування перезаписує дані за вказаним шляхом. [Документація mke2fs](https://github.com/tytso/e2fsprogs/blob/master/misc/mke2fs.8.in)

```bash
mkfs.ext4 -F -L loop-test test.img
```

Мітку `loop-test` буде видно в `lsblk`. Ext4 займає весь образ, тому таблиця розділів тут не потрібна.

### Під’єднуємо образ як блоковий пристрій

`--find` вибирає вільний loop-пристрій, а `--show` друкує його шлях.

```bash
sudo losetup --find --show test.img
```

Припустімо, команда повернула `/dev/loop12`.

```bash
lsblk -o NAME,TYPE,SIZE,FSTYPE,LABEL,MOUNTPOINTS /dev/loop12
```

У виводі буде `TYPE=loop`, `FSTYPE=ext4` і мітка `loop-test`. Колонка точки монтування ще порожня.

### Монтуємо ext4 і записуємо файл

Створіть порожній каталог для монтування всередині робочого каталогу.

```bash
mkdir mnt
```

Під’єднайте файлову систему до цього каталогу. Перейдіть до запису файла лише після успішного монтування.

```bash
sudo mount -t ext4 /dev/loop12 mnt
```

Створіть тестовий текстовий файл у робочому каталозі.

```bash
echo 'Цей файл збережено всередині образу ext4.' > hello.txt
```

Кореневий каталог нової ext4 належить root, тому для копіювання в нього використаємо `sudo`.

```bash
sudo cp hello.txt mnt/
```

```bash
cat mnt/hello.txt
```

Тепер є дві копії `hello.txt`. Оригінал лежить у робочому каталозі, а копія, доступна через `mnt/hello.txt`, зберігається всередині `test.img`.

### Відмонтовуємо й відкриваємо образ знову

Спочатку відмонтуйте файлову систему.

```bash
sudo umount mnt
```

Якщо `umount` повідомляє, що каталог зайнятий, вийдіть із нього в усіх терміналах і закрийте програми, які тримають відкриті файли. Після успішного відмонтування звільніть пристрій, який повернув `losetup`. [Документація losetup](https://github.com/util-linux/util-linux/blob/master/sys-utils/losetup.8.adoc)

```bash
sudo losetup --detach /dev/loop12
```

Каталог `mnt` знову порожній. Щоб відкрити образ повторно, передайте `mount` шлях до файла. Параметр `-o loop` доручає команді створити прив’язку автоматично.

```bash
sudo mount -o loop test.img mnt
```

```bash
cat mnt/hello.txt
```

Файл доступний після повторного монтування, бо його дані залишилися в образі. Після роботи відмонтуйте `mnt`. Автоматично створену прив’язку система звільнить, коли пристрій більше не використовується. [Документація mount](https://github.com/util-linux/util-linux/blob/master/sys-utils/mount.8.adoc)

```bash
sudo umount mnt
```

## Де ще використовують loop-пристрої

**ISO-образи.** Інсталяційний образ Linux можна відкрити як файлову систему й переглянути його вміст без запису на флешку. Для цього потрібні файл ISO і порожній каталог. Після роботи достатньо відмонтувати каталог.

```bash
sudo mount -o loop,ro ./installer.iso ./mnt
```

**Копії дисків із розділами.** Образ цілого диска може містити GPT або MBR, а файлові системи починаються всередині розділів. Для такого образу `losetup --partscan` просить ядро прочитати таблицю розділів. `--read-only` захищає вихідний файл від запису через цей пристрій. Після підключення дивіться дерево `lsblk` і вибирайте потрібний дочірній розділ. Відмонтуйте всі використані розділи перед від’єднанням батьківського loop-пристрою.

```bash
sudo losetup --find --show --read-only --partscan ./disk.img
```

Якщо команда повернула `/dev/loop13`, перегляньте його розділи так.

```bash
lsblk -o NAME,TYPE,SIZE,FSTYPE /dev/loop13
```

`--partscan` працює з образом, у якому доступна реальна таблиця розділів. Якщо файл має службові структури формату QCOW2 або VMDK, потрібна утиліта, яка розуміє цей формат і надає доступ до його логічних блоків.

**Тести й локальні лабораторії.** Невеликий ext4-образ дає змогу відтворити переповнення файлової системи, перевірити роботу з мітками чи параметрами монтування та підготувати вхідні дані для утиліти резервного копіювання. Розмір можна підібрати під тест. Якщо треба повторити дослід із початкового стану, достатньо взяти копію відмонтованого образу. Для оцінки швидкості реального диска такий тест має обмеження, бо на результат впливають також кеш і файлова система хоста.
